## Clusters
Group labels that refer to the same thing. For each cluster report:

- members: two or more labels from the list above that denote the same thing
- same_referent: true only if you believe every member denotes the SAME thing.
  Differing surface forms of one name ("Edwin Aldrin" / "Buzz Aldrin",
  "NASA" / "National Aeronautics and Space Administration") are the same thing.
  Two different things that merely share a word ("Armstrong" the astronaut and
  "Armstrong" the musician) are NOT.
- broader: true if one member is a strictly BROADER concept than the others
  rather than another name for the same thing — a mission programme versus a
  single mission in it, a field versus one technique within it. This is a
  warning flag, not a reason to omit the cluster: report the cluster with
  broader set to true and let a human decide.
- confidence: 0.0-1.0, how certain you are that the members denote one thing
- reason: ONE short sentence justifying the grouping

Do not group entities you are unsure about — leave a label out entirely and it
will simply stay as it is. A label you omit is never merged, so omission is the
safe choice. Never put a label in more than one cluster, and never report a
cluster with only one member.

Output ONLY a JSON object of the form {"clusters": [...]}. No markdown, no
explanation.
